# 동물 확장 구조와 품질 수정 TDD 근거

## 사용자 여정

- 사용자는 달리기·자기돌봄 기록에 맞는 칭찬을 받음
- 사용자는 같은 기록에서 다른 칭찬을 다시 받을 수 있음
- 사용자는 기록을 삭제해도 이미 만난 동물을 유지함
- 개발자는 데모 날짜로 해금을 시험하되 실제 진행도를 오염시키지 않음
- 개발자는 새 동물을 한 카탈로그 규격으로 추가함
- 사용자는 의미 없는 입력을 저장하지 않고 동물다운 재입력 안내를 받음

## RED

- 이후 `createConfusedResponse` 미구현 export로 이상 입력 반응 RED 확인

## GREEN

| 보장 | 검증 |
|---|---|
| 모든 동물이 이미지·색·외형·말투·주제별 4개 이상 칭찬을 가짐 | `src/praise.test.ts` 카탈로그 완결성 테스트 |
| `달리기`, `러닝`, `km`를 운동으로 분류 | 키워드 분류 테스트 |
| 물·식사·수면·휴식을 자기돌봄으로 분류 | 자기돌봄 분류 테스트 |
| 다시 받기에서 다음 칭찬으로 변경 | 칭찬 revision 테스트와 브라우저 실사용 |
| 실제 날짜만 영구 해금에 반영 | 진행도·데모 제외 테스트 |
| 기록 삭제 후 해금 진행도 유지 | 브라우저 저장소 검증 |
| 첫 화면에서 이미 등장한 토끼를 다음 해금으로 안내하지 않음 | 다음 해금 테스트 |
| 모션 감소 환경에서 300ms 이내 오버레이 제거 | Playwright 실사용 검증 |
| 도장 접근성 역할과 모바일 가로 넘침 정상 | Playwright DOM 검증 |
| 하찮지만 의미 있는 짧은 기록은 허용 | 정상 입력 판별 테스트 |
| 기호·자모·반복·키보드 난타는 기록하지 않음 | 이상 입력 판별 테스트와 브라우저 저장소 검증 |
| 이상 입력에 동물별 다른 반응 제공 | 카탈로그 완결성·반응 테스트 |

## 알려진 범위

- 앱인토스 `Storage` 실패는 브라우저 `localStorage` 대체 경로로 검증
- 실제 토스앱 샌드박스와 콘솔 업로드는 사용자 계정에서 최종 확인 필요
- 이미지 생성 자체는 자동 테스트 대상이 아니며 `docs/ANIMAL_GUIDE.md`의 시각 체크리스트로 관리
